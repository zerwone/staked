## Data model (`agents/`)
```
agents/
  roles.yml          # single source of truth for roles, lanes, status
  board.jsonl        # append-only task events
  questions.jsonl    # append-only owner-decision ledger
  DECISIONS.md       # numbered owner decisions, append-only, hand-written by owner
  HISTORY.md         # one line per handover, generated
  locks/<name>.lock  # claim/lock files
  inbox/<agent>/T-XXX.md     # specs, with frontmatter
  reports/T-XXX-<agent>.md   # reports, with frontmatter
  specs/             # shared interface contracts
  archive/           # pruned specs/reports
```

### board.jsonl (one JSON object per line)
`{"ts":"2026-11-08T12:00:00Z","task":"T-101","agent":"cursor","status":"DOING","note":"...","flags":[]}`
Statuses: TODO DOING BLOCKED REVIEW DONE PAUSED STOPPED. Latest event per task wins.

### questions.jsonl
`{"ts":"...","id":"Q-031","agent":"codex-2","text":"...","blocking":["T-101"],"default":"keep flags off","expires":"2026-11-10","status":"open","answer":null}`

### Spec / report frontmatter (YAML)
Spec: `task, owner, status (open|closed), allowed_paths, done_when`.
Report: `task, agent, flags (list), tests_run (list), native_boot (bool), files_changed (list)`.

## Commands (build in this order; each is its own commit `lanes: <cmd>`)
1. `lanes init [--agents a,b]` — scaffold `agents/`, write `roles.yml` template, add `.gitattributes` merge=union for the two jsonl files, print next steps.
2. `lanes gen` — generate `CLAUDE.md`, `AGENTS.md`, `.cursor/rules/lanes.mdc`, `GEMINI.md` per agent from `roles.yml` + open board items + open questions the agent owns. Target **< 6 KB** each. Include the 5 rules verbatim. Also generates `HISTORY.md` and the human-readable `agents/BOARD.md` view (open tasks only, deduped, newest first) — mark these files `<!-- generated by lanes, do not edit -->`.
3. `lanes claim <task> --as <agent> [--note]` / `lanes status <task> <STATUS> --as <agent>` / `lanes release <task>` — append to board.jsonl; `claim` refused if task is DOING/REVIEW for another agent, if agent already has a DOING task, or if agent is paused. Writes `locks/<task>.lock` with agent + TTL (default 8h).
4. `lanes lock <resource> --as <agent> [--ttl 2h]` / `lanes unlock` — same lock mechanism for `resources` in roles.yml (e.g. sandbox). Refused if held and not expired.
5. `lanes board` — print the open-tasks view (also what `gen` writes). `--all` includes DONE. `--json`.
6. `lanes ask --as <agent> --text ... [--blocking T-1,T-2] [--default ...] [--expires 2d]` / `lanes answer Q-031 --text ...` / `lanes questions [open]` — ledger ops. `questions open` prints only unresolved, ranked: blocking-most first, then oldest, each ≤ 2 lines. This is the owner's phone view; keep it tight.
7. `lanes check [--as <agent>] [--staged]` — pre-commit gate. Resolve agent from `--as`, env `LANES_AGENT`, or `git config user.name`. Fail if any staged path is outside the agent's lane (minimatch-style globs, implement yourself, no dep) unless path is under `agents/` and is that agent's own report/spec/row. Fail if a report for a task being set to REVIEW is missing required frontmatter or lists `files_changed` that don't match the staged diff. Install with `lanes hook install` (writes `.git/hooks/pre-commit`, preserves existing hooks by chaining).
8. `lanes handover <from> <to> [--lanes all|list]` — rewrite `roles.yml` (boss and/or lanes), append `HISTORY.md` line, rerun `gen`. Refuse if `from` holds a DOING task unless `--force-release`, which marks it PAUSED with a note.
9. `lanes report check <path>` — standalone validation of a report file (used by `check`).
10. `lanes prune` — move specs with `status: closed` and reports for DONE tasks older than 14 days to `agents/archive/`, regenerate.
11. `lanes doctor` — detects the ten failure modes from ORIGIN.md: stacked authority sections in markdown, duplicate task ids, hand-edited generated files (hash mismatch), lane overlaps in roles.yml, expired locks, questions past `expires` with no answer, agents with >1 DOING task, reports without `flags`.
